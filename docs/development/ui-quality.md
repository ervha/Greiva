# UIの滑らかさと見た目

2026-10-04の利用者指定。ドラッグ以外の操作にも、滑らかさと見た目の整い方を共通の品質基準として適用する。機能範囲・実装順は `docs/plan/POC_SPEC.md` に従う。

追加指定により、[Material 3](https://m3.material.io/)の丸み・柔らかな色と動き、[AppleのMaterials](https://developer.apple.com/design/human-interface-guidelines/materials)の透明感と内容／操作の階層を参考にする。Web/Tauriの既存UIへ取り入れる方針で、各OSのnative materialや動的壁紙色、Appleの光学効果そのものの実装を意味しない。本文は不透明で読みやすく、blurは候補など小さい補助surfaceへ限定し、非対応時は不透明へ戻す。

- 内容と操作の関係が伝わる動きにする。並び替えは元の横位置・幅を保って持った行を上下へ動かし、周りの行が場所を空ける。線だけを移動の主表現にしない。
- ハンドルの列をまっすぐ上下へ動かしてdropできるようにする。本文の上へpointerを横移動させる操作を要求しない。
- 色、余白、角、影、フォーカス、動く時間と加減速を揃える。大きな装飾・跳ねる動き・長い待ちで入力を妨げない。
- Hover・押下・選択・開閉の変化は短く、途中で操作を反転できるものにする。保存・同期表示の更新で入力面を動かしたり、本文を再生成したりしない。
- 本文や候補の位置を変えるアニメーションは、IME composition、カーソル、選択、キーボード操作と両立させる。DOMの表示変更を保存内容・Undo履歴へ混ぜない。
- `prefers-reduced-motion: reduce` では移動・回転・出現のアニメーションを止め、状態差と操作性を残す。常時点滅、不要な無限アニメーションは使わない。
- Pointerとkeyboard、狭い画面、長い日本語、Todo・Toggleなどの異なる高さを確認する。Dockerの操作結果とWindows実IME／物理操作の証拠を区別する。

まず既存Editor・ボタン・候補メニュー・Toggleの範囲で揃える。本番の新画面や新機能をこの方針だけで追加しない。正式なnative性能やGateの合格をCSSの改善から推定しない。
