# Step 8: Microsoft IME再変換の受入例外

2026-10-03、利用者は「マイクロソフトIME自体のバグなので無視してよさそうです。ほかのアプリ複数で同様の症状が出ました」と指示した。これを現在のWindows環境での選択後window移動＋再変換について、Greivaの修正待ちから外す判断として採用する。追加の確認を待たず、他のPoC検証へ進む。

[通常0.6.9 A/Bと診断0.6.5 C/Dの証拠](../../tests/evidence/windows-ime-reconfirm-20261003/SUMMARY.md)では、移動なしは本文保持、移動ありは直前の `al ` が欠落。素のtextareaでもnative削除範囲の拡大を観測した。他アプリでの同症状は利用者報告であり、OS／IME／WebView2内の根本原因や上流の修正予定は未確認。

本文保持の観測Failは保存し、Passへ変更しない。Gate Aの最終資料では、この条件の受入例外と利用者判断を明記する。従来の「この再変換Failを解決するまで最終判断不可」という作業上の制約は解除する。通常変換、遠隔更新、他の必須操作、保存・収束・crash、Android実OSの未実施条件は従来どおり検証する。製品への入力回避策、IME／OS設定変更、runtime更新、外部への報告送信は今回行わない。
