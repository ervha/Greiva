# 自律判断の全件記録とPoC完了時の引継ぎ

2026-10-04／v0.6.23、製品0.6.20。利用者は不在時も可能な作業を進め、必要な事項をまとめるよう指定し、さらに「これまでの判断や資料をもとにそちらで判断できることであれば自律的に判断してもよい。ただし、その判断内容は必ず記録し、停止する前にその判断した内容すべてをまとめて書き出しておくこと」と委任した。

## 今回確定した判断すべて

1. **連続入力の確認待ちを解消。** 利用者の問題なし報告とSQLite30→76更新・1,000段落・他999段落保持・peer収束を採用する。追加24 UTF-16単位という実範囲を記録し、2〜3文・長時間・frame SLOを推定しない。[監査](../../tests/evidence/poc-gate-review-20261004/SUMMARY.md)。
2. **Gate AをPass（受入例外あり）に確定。** 通常／遠隔Microsoft IME、必須block、物理drag、保存証拠を統合。以前のAlt+Tab再変換欠落は利用者の既存例外に限定し、上流バグの独立証明や原Failの修正を主張しない。[Gate A](gate-a.md)。
3. **Gate BをConditionalに確定し、次Gateへ進む残条件を委任の範囲で受入。** P0正確性に新たな再現可能なFailはなく、P1/P2不足と性能測定課題は仕様§15のConditionalに対応する。Docker実Rust全境界と通常Windows境界の違いも保持。無条件Passや利用者による個別リスク承認へ読み替えない。[Gate B](gate-b.md)。
4. **Gate CをPassに確定。** durable ACK／再送／cursor／Conflict／大量操作の整合証拠と、v0.6.11→0.6.20の関連source不変に基づく。旧試験の実行版を最新へ書き換えない。server応答間約76秒をnative end-to-end SLOと扱わない。[Gate C](gate-c.md)。
5. **技術基盤を条件付き採用。** PageのTiptap／Yjs／HocuspocusとSQLite、structuredの操作／cursor／ConflictとNestJS／Fastify／PostgreSQLを継続する。基盤置換は行わない。[技術選定](poc-technology-selection.md)。
6. **追加の手操作を今は要求しない。** 既に受入済みの0.6.19物理dragを再依頼しない。0.6.20の自動drag未移動と旧0.6.17空段落原因未確定は残す。日本語連続入力を繰り返し依頼しない。
7. **自由入力は公開しない。** 公開証拠を長さ・hash・監査scriptに限定。SQLite／全文peer／入力を映した画面は.data内に保持する。保存は直接DBで証明し、今回読めなかった保存ラベルを観測したとはしない。
8. **製品の版と検証checkpointを分離。** 文書・検証PATCH v0.6.23。製品source／manifest／既存exeは0.6.20のまま。新コードがないため59 E2Eを重複実行せず、文書リンク・監査整合・差分を検証してcommit／tag／pushする。
9. **PoC Step 9で今回の作業範囲を完了。** 仕様§17/18のGate記録と技術選定を作成し、全Gate無条件Passとは呼ばない。Calendar／AI／認証・本番提供への範囲拡大を行わず、ここで開発を区切る。Computer Use解除を維持し、既存Pageを編集しない。
