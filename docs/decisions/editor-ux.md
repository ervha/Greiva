# Step 2: Slash・Toggleの操作改善

ユーザーが既存プレビューの見た目を了承したうえで、トグルや「/」候補の細部を洗練するよう指定した。PoCの必須Editor範囲で改善し、同期・永続化は追加していない。

## 候補選択

- アイコン、説明、カテゴリを付け、キーボード操作を下端へ表示。長い一覧は候補部分だけをスクロールし、画面の空きに応じて入力行の上・下へ配置する。
- マウスで指した候補を矢印キーの選択へ引き継ぐ。ハイライトは常に1つ。クリック・Enter・Tabのいずれも入力フォーカスをEditorへ保つ。
- 上下キーは端で循環、Home/Endで先頭・末尾へ移動。検索語が変われば先頭へ戻し、同じ検索語の再描画では選択IDを保つ。
- `/h1`〜`/h3`、`/トグル`、`/タスク`などの検索語を追加。候補なしを説明し、Escape・一覧外クリックで入力文字を残して閉じる。
- optionの名前・説明、選択状態、件数、Editorのactive descendantを明示する。DOM操作とキー処理はcompositionを消費しない。

## トグル

- 作成時は開いた状態で見出しにフォーカス。空の見出し・本文には入力位置の案内を表示する。
- 見出しでEnterを押すと既存本文の先頭へ移動する。空段落を追加し続けない。閉じている場合は開いてから移動する。
- Ctrl/Cmd+Enterは選択位置に最も近いトグルだけを開閉する。本文を閉じるとカーソルを見出しの末尾へ移す。
- ポインターで開閉しても選択を保持し、本文へ戻せる。開閉ボタンをキーボードで操作するとボタンのフォーカスを維持する。
- 開閉だけの操作は本文のUndo履歴へ入れない。ネスト、解除、保存するopen属性は既存スキーマを維持する。
- 開閉ボタンを32pxへ広げ、SVG矢印・状態ラベル・フォーカス表示を付ける。短い回転表示はreduced motion設定では停止する。
