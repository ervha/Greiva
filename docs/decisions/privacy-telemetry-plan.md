# 規約・プライバシー・任意改善データの判断記録

2026-10-05。利用者が最終設計への追加を依頼し、日本先行・エラー/性能のみと回答。以下は設計判断であり実装/法的適合の合格判定ではない。

1. 公開対象を日本先行とする（利用者回答）。海外提供と国外委託先の取扱いを分けて確認する。
2. 改善対象はエラー/性能のみ（利用者回答）。機能利用analytics・広告・AI学習・操作履歴を含めない。
3. 初期OFF、明示opt-in、いつでもOFF、主要機能に影響しない任意設定とする（自主判断）。規約同意と分離する。
4. 同意は端末ごとに取得し、他端末/新install/復元/account切替へONを継承しない（自主判断）。
5. 初期送信は認証済み主体＋登録端末に限定する（自主判断）。未ログインの自動送信は行わず、匿名と誤表示しない。
6. 固定エラーcode/集計性能値だけを許可し、本文・入力・自由文字列/stack/添付・秘密・ユーザーresource IDを排除する（自主判断）。
7. 同意登録確定前は収集も開始しない。UI、収集/送信、server受信の各段階で検証する（自主判断）。
8. 同意revision/CAS/冪等mutation、受信とのtransaction境界、ローカルgenerationで撤回と遅着/再送を扱う（自主判断）。
9. OFFは即時停止・未送信削除、offline撤回はdurableに優先再送する。既受信データの取消/即時全削除を約束しない（自主判断）。
10. 同意範囲拡大は再同意を要する。手動診断添付、AI許可、必要なサービスログは別目的/操作とする（自主判断）。
11. 保持日数・Provider・保管国・窓口・料金/管轄等を創作せず公開前の未決事項にする（自主判断）。AIの30日保持を流用しない。
12. データフロー台帳と実装/文書/通信照合、専門確認、offline参照、撤回/削除の試験を公開品質ゲートにする（自主判断）。PoC範囲へ収集を追加せず、設計完了後は既存のP1 HTTP開発を続ける（利用者指示）。

詳細なschema/操作/受入は[改善データ仕様](../plan/PRIVACY_TELEMETRY_SPEC.md)、法的文書の構成・未決事項・一次資料は[規約/ポリシー計画](../plan/TERMS_PRIVACY_POLICY_PLAN.md)。追加の手操作や今すぐの外部環境作成は求めない。
