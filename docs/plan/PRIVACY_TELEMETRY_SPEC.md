# 任意の改善データ送信・同意設計

2026-10-05。製品設計の追加。利用者の回答は「まず日本」「エラー・性能だけ」。未実装であり、既存PoCに収集や外部送信を追加しない。[規約・ポリシー計画](TERMS_PRIVACY_POLICY_PLAN.md)、[判断記録](../decisions/privacy-telemetry-plan.md)を参照。

## 1. 目的と範囲

クラッシュや保存・同期エラーの傾向、起動・保存・同期等の処理時間を把握し、安定性と速度の改善に使う。広告、行動追跡、機能利用率、ユーザー内容の分析、AI学習には使わない。機能利用状況のanalyticsは今回の対象外。操作履歴・セッション録画をエラー調査の名目でも収集しない。

任意送信は初期OFF。明示的に同意した端末だけで計測・収集・送信する。規約への同意、アカウント作成、同期の有効化、更新インストールは、この同意を兼ねない。拒否や撤回でPage編集・端末保存・契約された同期を制限しない。これはGreivaの製品方針であり、個人情報の全取扱いに一律の同意が法定されるという説明ではない。

## 2. 設定画面

「設定 → プライバシー → アプリ改善」の項目を設ける。

| 要素 | 表示・操作 |
| --- | --- |
| スイッチ | 「エラー・性能データを送信する」。初期OFF、端末ごと |
| 説明 | 「Greivaの安定性と速度の改善に使います。本文・入力内容・機能の利用履歴は送りません。いつでも停止できます。」 |
| 詳細 | 実際の項目例、送信先・保管国、保持期間、識別子、削除/問い合わせ、ポリシーの版とリンク |
| ONにする時 | 詳細を表示し「同意して有効にする／キャンセル」。未選択や閉じる操作では有効化しない |
| OFFにする時 | 確認を強制せず直ちに停止。収集・未送信キュー削除は即時、サーバーへの撤回反映は別の状態として表示 |
| 状態 | OFF／同意登録待ち（未収集）／有効／送信保留／撤回反映待ち／再同意が必要。失敗を有効化成功と表示しない |
| 法的文書 | 利用規約とプライバシーポリシーへの常設リンク、版・施行日。配布版対応の文書を同梱しofflineでも参照可能 |

keyboard、screen reader、Android touchに対応し、label・focus復帰・状態通知を持つ。設定を開いたりスイッチを扱ったりして本文のIME compositionや保存を妨げない。未ログイン時は説明とOFFを表示できるが、初期の自動送信は認証・端末登録後に限定する。ログインを求めてまで送信へ誘導しない。

ONの状態を他端末へ同期しない。新規端末・再インストール・account切替はOFF。設定の復元/旧DB取り込みでも同意を推定しない。logoutはローカル収集停止・キュー削除とし、通常データのlogout時保持/消去方針は別契約。

## 3. データ最小化

固定schemaの許可項目だけを採用する。エラー時の自由文字列や例外object全体をserializeしない。

| 候補項目 | 制約 |
| --- | --- |
| event ID、schema/purpose版 | 再送重複防止、互換性/目的範囲の照合。イベントごとの乱数ID |
| アプリ版、platform、OS major | 互換性調査用。正確な端末名、serial、広告ID、位置情報は送らない |
| error code、固定component code | ソースに定義した列挙値。ユーザーの文字列をcodeに混ぜない |
| latency histogram、処理失敗数 | 固定処理種別、集計期間内のbucket/count。クリック・画面遷移・機能別利用回数や時系列操作列を作らない |
| 同意参照・端末登録参照 | 認証済み主体と端末にサーバー側で結び付け、同意照合に必要な最小参照に限る。analytics用profileを作らない |

本文、Page/Taskタイトル、Property値、検索語、入力文字・IME候補、音声、AI会話、clipboard、ファイル/画像、スクリーンショット、Yjs binary、DB dump、workspace/entity/document ID、URL/query、任意stack trace、email、token、cookie、Authorizationヘッダー、ローカルpathはpayload・ログ・exportに含めない。ログを後からredactするだけに依存せず、収集源から固定値と集計値に限定する。

端末登録参照や同意記録が主体へ結び付くため「完全匿名」と表示しない。通信ではIP等が受信側に見える。proxy/CDN/SDKも含めた受信ログの項目・保持・国・委託先を調査し、任意送信の説明とポリシーへ反映する。IPを改善イベントへ保存/付加しない。匿名加工情報等の法的分類は実際の処理に基づき確認する。

自動crash SDKの標準breadcrumb、添付、session replay、未同意時の起動通信は許可しない。将来採用する場合も上記契約を満たすまで収集を無効にする。手動の診断export/問い合わせは、内容と送信先を利用者が確認する別操作。任意送信への包括同意を添付送信へ流用しない。

## 4. 同意と受信の契約

Applicationに同意portと改善イベントportを設け、同期operation/CRDTとは別の経路・保管領域にする。telemetry不通は本文保存・同期の失敗にしない。初期は既存の認証済み主体（issuer＋subject）と登録端末を使い、未認証・端末未登録・他主体・失効sessionを拒否する。

同意記録の候補は主体、端末参照、purpose version、提示文書/説明の版またはhash、状態、サーバー確定時刻、単調増加revision、mutation ID。受信イベントはevent ID、同意revision、schema/purpose version、許可された集計payloadを持つ。クライアントの `consent: true` や時刻だけでは受理しない。主体はverified sessionから取り、自己申告subjectを信用しない。

同意変更はサーバーの現在revisionと照合するCASとして扱い、同じmutation IDは冪等に処理する。古いON、再送、account/device違い、unknown purpose/schemaを拒否する。OFFへ切り替えた時は新しいローカルgenerationでキューと送信予約を破棄し、古い応答からONへ復帰しない。撤回待ちがある間の再ONは、撤回確定後に新しい明示同意として実行する。

収集開始は、有効な同意のサーバー確定と端末へのdurable保存後。開始前のエラーをためて後で送らない。収集・enqueue・send直前にローカル状態を検証し、受信側も現在の同意・主体・端末・版を検証する。同意照合とイベントの永続化は同じtransaction/整合性境界に置き、撤回が確定した後の旧revisionを拒否する。撤回前に受信済みのデータは「停止」と別の削除/保持契約で扱う。

OFFはofflineでも直ちに収集停止し、未送信キューを消す。送信中のrequestは可能な範囲で中止するが、既に受信された通信を取り消したと表示しない。撤回操作をdurableに記録して再接続で優先送信し、サーバー確定前は「この端末で停止・撤回反映待ち」と説明する。同意台帳が不通/不明なら新しいイベントを受理しない。

同意状態が有効な場合のoffline集計は、内容を含まないサイズ/期限付きqueueとする。具体的な容量・期限・sampling/集計窓は公開前に確定する。overflow/期限切れは改善イベントだけを破棄し、通常データや撤回記録を巻き込まない。再送はevent IDで重複除外する。受信入口にbody上限・rate limit・未知field拒否を置き、拒否payloadや認証headerをログへ出さない。

収集項目・目的・受信者等の実質的な拡大は新purpose versionと再同意を要する。既存同意を新範囲に流用しない。未対応/旧版は停止し、同意UIを経由する。文言だけの修正と範囲拡大の判定、通知方法を変更管理で記録する。

## 5. 保持・削除・運用

サーバーraw event、集計、同意記録、撤回記録、proxyログ、backupごとに目的・閲覧者・保持期限・削除手順を確定する。AI会話/録音の30日設定は改善データへ流用しない。日数が未決定のまま公開収集を開始しない。撤回後の既受信データの扱い、削除依頼の本人確認・検索/削除・backup反映・完了通知を文書と実装で一致させる。

閲覧は必要な担当者に限定し、アクセス監査・漏えい対応・委託先監督を設計する。改善受信先の未設定/停止時はoptional pipelineだけ無効化する。サービス提供に必要な認証・不正利用対策等のログは目的・項目・保持を別に明示し、任意送信OFFで全server logが無くなると約束しない。任意telemetryを必須ログへ付け替えて収集しない。

## 6. 実装順と受入

P1の認証/端末境界とP2の設定基盤に依存する。先に収集項目・同意schema・保持/送信先契約を確定し、Domain/Applicationのdeny-by-default、設定UI、受信transaction、限定した計測点の順で実装する。P4の公開ゲートに規約・実データフロー照合を追加する。未完了なら任意送信は提供せずOFFのままとし、未実装スイッチを操作可能な機能として見せない。

| 試験 | 必須結果 |
| --- | --- |
| 初回・拒否・未ログイン・新端末・account切替・再install | optional collector/queue/送信が起動しない。主要操作を利用可能 |
| ON取消/登録失敗・遅着応答 | 収集しない、成功表示なし。古い応答で再有効化なし |
| 有効化 | 説明版・目的版・端末と主体の同意が一致した後だけ許可 |
| OFF・offline撤回・再接続・app kill/restart | 即時停止、未送信破棄、撤回復元/優先反映、旧event再送拒否 |
| 同意改ざん・他主体/端末・期限切れ・不通・unknown版 | server側拒否、永続化なし、入力や秘密をログへ出さない |
| 同時撤回/送信・ON再送順序逆転 | 確定撤回後の旧revision拒否。送信成功を取消済みと誤表示しない |
| 内容/例外への秘密混入 | payload・収集キュー・受信ログ・exportから禁止項目が漏れない。自由文字列field拒否 |
| 重複・queue上限・受信不通 | 重複集計なし、上限を守り、本文保存/通常同期を妨げない |
| 目的変更・削除/保持・backup | 再同意前は新範囲なし、確定保持契約どおり削除/説明 |
| Windows/Android設定UI | touch/keyboard/accessibility、offline文書、focus/IME/端末保存維持 |

現時点で以上の機能・受入は設計であり、新しい試験Passを意味しない。
