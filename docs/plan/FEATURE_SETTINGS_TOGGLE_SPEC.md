# 機能・設定項目トグル切り替え設計仕様 v0.1

更新: 2026-10-06。ユーザー指定に基づき、Greiva内の設計項目（機能モジュール）および設定項目（エディタ動作、同期、プライバシー、AI）をユーザーがON/OFFトグルで切り替え可能にするための仕様を定義する。
本書は仕様設計・要件定義であり、実際のコード実装や即時リリースを意味しない。基盤要件は `GREIVA_REQUIREMENTS.md`、UI標準は `GREIVA_DESIGN_SPEC.md`、データ永続化は `DATA_MODEL.md` に従う。

## 1. 目的と基本原則

### 1.1 目的
Greivaはノート、タスク、予定、AIなどを包括的に統合するサービスを目指しているが、利用者のニーズや作業コンテキストは多様である（例: 余計なパネルのない軽量なテキストエディタとして使いたい、タスク機能だけを併用したい、AI機能を完全に無効化したい、など）。
利用者が自身の用途に合わせて不要な機能をOFFにし、必要な機能のみをONに選択できるトグルスイッチを提供することで、認知負荷の低いシンプルでパーソナライズされた利用体験を実現する。

### 1.2 設計原則
1. **非破壊性の原則（Non-destructive Toggle）**:
   機能トグルをOFFにしても、端末内またはサーバー上に保存されている実データ（作成済みのTask、Relation、Calendar予定、AI作成履歴など）は決して削除・破棄されない。UI上の導線や実行処理のみが隠蔽・停止され、再度ONにした際には過去のデータが完全に復元・再表示される。
2. **Local-firstと即時反映**:
   設定変更は端末内SQLiteに即時記録され、オフライン環境下であっても即座にUIへ反映される。
3. **明確なスコープの分離**:
   「端末ローカル設定（この端末のみ適用）」と「ワークスペース設定（全端末に同期）」の境界を明確に区別し、ユーザーに混乱を与えない。
4. **安全なデフォルト値**:
   初期状態では最も安全・軽量かつ直感的な状態をデフォルト値とし、実験的機能や外部通信を伴う機能は安全側（OFFまたは明示的確認）に倒す。

## 2. トグル項目の体系と分類

設定項目は以下の4つの大分類に整理し、設定画面から一覧で切り替え可能とする。

### 2.1 機能モジュール（Feature Modules）
画面構成やデータ連携に関わる大きな機能単位の有効/無効トグル。

| 項目ID | 項目名 | 説明 | デフォルト | 影響範囲 |
| --- | --- | --- | --- | --- |
| `module.tasks` | Task・Relationパネル | ノート下部または専用ビューでのタスク登録・関連付け機能の表示 | ON | UIパネル・導線の表示切替 |
| `module.calendar` | Calendar・定期予定・時間割 | 予定表ビュー、時間割プリセット、定期予定の管理機能の表示 | ON | ナビゲーション・ビューの表示切替 |
| `module.database` | 汎用データベースビュー | Notion互換のTable, Board, Timeline等の高度なDBビューの利用 | OFF（段階提供） | DBビュー作成・切替UI |
| `module.ai_actions` | AI・音声アシスタント | 文章・音声によるノート作成、タスク抽出、要約支援機能の提供 | OFF（初期設定） | AI入力パネル・録音ボタンの表示 |
| `module.help_support` | ヘルプ・利用案内ガイド | 画面内のコンテキスト操作案内、ショートカット一覧、FAQへの導線 | ON | サイドバー導線・ヒント表示 |
| `module.experimental` | 実験的機能（ラボ） | 開発中・検証段階のプロトタイプ機能の先行試用 | OFF | 実験的フラグの個別有効化 |

### 2.2 エディタ・入力動作（Editor & UX Behavior）
執筆中の操作感や入力補助に関する細かな挙動のトグル。

| 項目ID | 項目名 | 説明 | デフォルト | 影響範囲 |
| --- | --- | --- | --- | --- |
| `editor.slash_menu` | スラッシュコマンド（/） | 行頭での `/` 入力時にブロック選択メニューを表示する | ON | エディタ入力補完 |
| `editor.mention` | メンション補完（@） | `@` 入力時にPage・Taskへのリンク候補メニューを表示する | ON | エディタ入力補完 |
| `editor.drag_handle` | ブロックドラッグハンドル | ブロック左側に移動・操作用のドラッグハンドルを表示する | ON | エディタDOM表示 |
| `editor.markdown_auto` | Markdown記法の自動変換 | `#` や `-` などの記号入力で行頭ブロックを自動変換する | ON | 入力イベント変換 |
| `editor.ime_safety_guard` | 日本語IME保護ガード | 変換中の誤変換・文字欠落を防ぐ厳格な合成イベント制御を適用する | ON | キー入力・イベント処理 |
| `editor.compact_view` | コンパクト行間モード | ブロック間の余白を詰め、一画面により多くの文章を表示する | OFF | エディタスタイル・レイアウト |

### 2.3 同期・ストレージ（Sync & Storage Preferences）
データの送受信およびローカル保存の挙動に関するトグル。

| 項目ID | 項目名 | 説明 | デフォルト | 影響範囲 |
| --- | --- | --- | --- | --- |
| `sync.local_only_mode` | ローカル完結モード | 外部ネットワークへの同期を完全に遮断し、端末内SQLiteのみで動作させる | OFF | 通信トランスポートの完全停止 |
| `sync.background_auto` | 接続時の自動同期 | ネットワーク復帰時にバックグラウンドで自動的に変更を同期する | ON | 同期エンジンの自動実行 |
| `sync.show_save_indicator`| 保存状態の詳細表示 | ヘッダーに「端末へ保存中…」「同期済み」等の文字ステータスを表示する | ON | ステータス表示バー |
| `sync.conflict_notifications`| 競合発生時の通知 | 同一フィールドで競合が発生した際に解決キューのバッジを表示する | ON | バッジ・通知UI |

### 2.4 プライバシー・AI・保守（Privacy, AI & Maintenance）
データ送信許可、保持期間、およびアプリ更新に関するトグル。

| 項目ID | 項目名 | 説明 | デフォルト | 影響範囲 |
| --- | --- | --- | --- | --- |
| `privacy.telemetry` | 品質改善・エラー送信 | 不具合修正・性能改善のための匿名診断データを送信する（初期OFF） | OFF | テレメトリ送信クライアント |
| `privacy.audio_cloud_backup`| 録音音声のクラウド保存 | 音声メモの元音声ファイルをクラウドへバックアップすることを許可する | OFF | 音声アップロード境界 |
| `ai.confirm_before_create` | AI作成時の事前確認 | AIが新規ノートやタスクを作成する際にも、実行前にプレビュー確認を行う | OFF（新規は直接実行が標準） | AI操作実行パイプライン |
| `app.auto_update_check` | 起動時の自動更新確認 | アプリ起動時に新しいバージョンの有無をバックグラウンドで確認する | ON | アップデーター確認処理 |

## 3. データ永続化とスコープの仕様

### 3.1 端末ローカル設定（Device Local Settings）
端末固有の事情（ハードウェア性能、入力方式、プライバシー設定など）に紐づく項目は、端末内SQLiteの `local_settings` テーブルに記録する。

- **テーブル設計（SQLite）**:
  ```sql
  CREATE TABLE IF NOT EXISTS local_settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at TEXT NOT NULL
  );
  ```
- **特徴**:
  - アカウント認証やサーバー同期の状態に依存せず、アプリ起動直後から同期不要で即座に読み込まれる。
  - 対象: `editor.*`, `sync.local_only_mode`, `privacy.telemetry`, `app.*` など。

### 3.2 ワークスペース設定（Workspace Settings）
複数端末間で共通化すべきプロジェクト単位の機能設定は、ワークスペースのメタデータに含めて構造化同期（Structured Sync）の対象とする。

- **対象**: `module.tasks`, `module.calendar`, `module.database` などの機能モジュール有効化フラグ。
- **特徴**:
  - 同一ワークスペースを開いている他の端末（デスクトップ、モバイル）でも同じ機能構成が再現される。
  - 変更時は操作ログ（Operation Ledger）として記録され、cursor経由で各端末に安全に配信される。

## 4. UI/UX 仕様

### 4.1 設定画面の構造
設定画面内に「機能とカスタマイズ」セクションを新設し、グループ化されたリスト形式で表示する。

```text
Settings
├─ アカウント・ワークスペース
├─ 機能とカスタマイズ（Feature Toggles）
│  ├─ 利用機能モジュール
│  ├─ エディタ・入力補助
│  ├─ 同期とデータ
│  └─ プライバシーとAI
├─ 外観・アクセシビリティ
└─ ヘルプとアプリ情報
```

### 4.2 トグルUIコンポーネント（Material Design標準）
- **コンポーネント仕様**:
  - 視覚的に状態が明確なスイッチ（Toggle Switch）を使用。
  - ON状態: ニュートラルなグリーン系アクセント（v0.25.1の控えめなパレットに準拠）。
  - OFF状態: ニュートラルグレーのアウトライン。
- **アクセシビリティ（A11y）要件**:
  - `role="switch"` および `aria-checked="true|false"` を付与。
  - 各項目に `aria-labelledby` または `aria-describedby` で詳細説明を紐づける。
  - キーボード操作（Tab移動、Space/Enterキーによる反転）に完全対応。
  - スクリーンリーダーで状態変更が即時通知されること。

### 4.3 連動・依存関係のハンドリング
- ある機能モジュールをOFFにした場合、その機能に依存する子設定項目（例: TaskモジュールOFF時のTask通知設定など）は、グレーアウト（`disabled`）表示とし、無効化されている理由を注記する。
- 親モジュールを再度ONにした場合、子設定の過去のON/OFF値がそのまま復元される。

## 5. 後続実装に向けた受入基準（Gate）

本仕様を実装・検証するフェーズでは、以下の条件を満たすことを確認する。

1. **データ保持確認**:
   TaskやCalendarを登録した状態で該当モジュールをOFFにし、再起動後もDB内にデータが存在し、再度ONにした際に欠損なく表示されること。
2. **パフォーマンス**:
   全トグル設定の読み込みがアプリ初期起動時間に与える影響が5ms未満であること。
3. **ローカル完結モードの確証**:
   `sync.local_only_mode` をONにした場合、HTTPリクエストやWebSocket接続が一切発行されないこと。
