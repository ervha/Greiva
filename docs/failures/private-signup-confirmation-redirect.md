# 確認メール後のlocalhost接続エラー

2026-10-13 / Windows専用候補0.82.0。

利用者が新規登録後の確認メールのリンクを開くとlocalhostへ移動し、接続できないと報告した。その後、Greivaへ戻ってログインできたと回答した。メール本文/確認URL/fragment/token/メールアドレスは取得・記録しない。

期待：確認後に、完了を理解してGreivaへ戻れる表示・導線がある。

実結果：戻り先の接続エラーが表示された。正常ログインは成立したが、確認完了画面・callback導線は未整備。戻り先portや実provider内のSite URL値は未取得なので、接続拒否の具体的なport/設定値を断定しない。登録adapterはredirect overrideを送らず、provider既存Site URLを使用している。

現在の操作：確認リンクを開いた後、Greivaの「ログインに戻る」からログインする。確認メールが届いたことやリンク遷移だけで認証成功を表示しない。

残作業：確認完了landing、許可済みredirect/callback、tokenを画面/ログへ残さない戻り方、期限切れ/拒否/配送制限の案内を整理する。providerの安全設定を勝手に変更しない。この事象を正常ログインの失敗や既知IME Failと混同しない。
